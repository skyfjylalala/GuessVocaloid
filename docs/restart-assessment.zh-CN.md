## 数据获取及再生数筛选

已核实 [amiadesu/VocaDBSongs](https://huggingface.co/datasets/amiadesu/VocaDBSongs) 存在。文件列表显示 `vocadb.csv` 约 1.92 GB，另有 URL 文件；歌曲子集约 77.2 万行。这里只检查了说明、结构及五行样本，没有下载或全面审计整个快照，也没有把文件上传日期当作所有记录的采集日期。

抽样通过 Hugging Face 的 rows API 完成。字段包括 `songType`、`originalVersionId`、`additionalNames`、`artists`、`tags`、`pvs`、`views`、时长、日期和 BPM。`views` 是按平台保存视频 URL 和播放量的 JSON 字符串，不能直接按一个数值列排序；其他嵌套字段也应正确解析。

建议的导入过程：

1. 离线读取 CSV，保留来源版本、导入日期和原始记录。使用正规 CSV 解析器及分批读取，避免把约 2 GB 的文件全部装进内存。
2. 解析播放量及 PV 元数据，尽量匹配原作者投稿；将找不到可信播放量的记录标记为未知，不填成零。
3. 优先保留 Original，排除翻唱、伴奏、重复版本，按 VocaDB ID 及版本关系处理重复。
4. 按平台设再生数门槛或取前 N 首，再取并集。第一轮可试 Niconico 百万再生；具体阈值和曲数根据实际筛选分布决定。不要直接把各平台、转载及多个视频的数字全部相加。
5. 输出精简曲库及质量报告，作为固定版本发布。播放量更新与用户游玩解耦；初期不承诺实时同步。
6. 用筛选后的数据支持猜测和答案。需要更宽的猜测范围时，再建立比答案池更大的搜索池；无需先提供全库搜索。

完整快照可留在本地 SQLite 做分析；云端 D1 只放筛选后的游戏数据。几百或几千首歌曲不需要托管全量数据库。生成静态歌名／别名索引让浏览器搜索，可进一步减少 API 和数据库查询。

## 属性和搜索规则

初版优先比较：主唱、作曲／主要 P 主、发表年份、时长；BPM 数据可用时加入。曲风标签和再生数提示可以后续补充。筛选采用再生数，不代表必须把实时再生数也作为比较维度。

- 用歌曲和艺人的 ID 比较，显示名称独立存储。
- 主唱与合作作者用集合表示，区分完全一致、部分相同、不相同；按参与角色过滤，不能把画师都算作 P 主。
- VocaDB 实测例子：`ローリンガール` 的艺人列表含初音ミク，以及 `isSupport: true` 的 GUMI。提取所有 Vocaloid 类型艺人会影响主唱提示，需要明确伴唱是否参与比较。
- 日期用歌曲发表日期，不用数据库录入时间；时长和日期缺失显示未知。
- BPM 需请求 `fields=Bpm` 才返回。实测该曲得到 `195000` milliBPM，即 195 BPM；没请求字段与字段本身缺失应区分。变速曲保留区间。
- 搜索用原名、英文／罗马字、别名，并做 Unicode NFKC 和大小写归一化。中文常用名不能假定每首都有，可维护独立覆盖文件。
- 本地别名和纠错作为覆盖层，重新导入时保留。

## 部署建议与费用边界

推荐将 Vite 构建产物和少量 API 部署到同一个 Cloudflare Worker，使用 D1 存精简歌曲、关联艺人和每日题目。官方提供 [React + Vite 接入方式](https://developers.cloudflare.com/workers/framework-guides/web-apps/react/)。本地通过 Wrangler 开发、迁移和导入，先使用平台子域名。

截至评估日的官方免费额度：

- [Workers](https://developers.cloudflare.com/workers/platform/pricing/)：每天 10 万次动态请求，每次 10ms CPU；静态资源请求免费且不限次数。它不是每天 10 万名玩家。
- [D1 计价](https://developers.cloudflare.com/d1/platform/pricing/)：每天读 500 万行、写 10 万行，账户总存储 5 GB；[单个免费数据库上限](https://developers.cloudflare.com/d1/platform/limits/) 是 500 MB。扫描行数而非返回记录数消耗读取额度，因此避免每个按键都全表搜索。
- 免费额度内可实现基础托管月费为零；超额会有服务限制，不能保证永久免费或大陆所有网络都访问稳定。部署后应让实际朋友测试。自购域名另计，不是首发必需。
- [Vercel Hobby](https://vercel.com/docs/plans/hobby) 可以承载非商业个人项目，保留 Next.js 并继续 Vercel 是可行备选；其免费计划限定个人非商业用途，之后加广告／收费时需重新确认方案。

## 判题与范围

出题及属性比较放在 Worker。浏览器拿歌曲搜索索引和每次猜测反馈，当前答案及未来排期不放进公开资源。练习模式也不要把答案 ID 明文返回前端再本地判题。

进度、偏好和个人成绩先存在 localStorage；匿名会话即可，不做账户和排行榜。这样不需要强防作弊系统，但服务端仍应验证歌曲 ID、限制请求大小并防止明显滥用。

每日模式固定换日时区并在界面说明。每日题目保存明确日期和题库版本，避免题库扩容导致同一天的答案变化。

首个可发布版本可以包含：无限练习、8 次机会、明确比较反馈、中日英界面和歌曲别名搜索、刷新保留进度、结束后原投稿链接及成绩分享、数据来源说明。先用小批真实数据贯通导入到部署，再按再生数扩充；每日模式随后接入，不必等待登录、多人对战或全量增量同步。

## 许可核实

[VocaDB License](https://wiki.vocadb.net/docs/license) 允许署名使用数据库内容，包括商业用途，数据库采用 CC BY；图像、音频、歌词等第三方内容不在该授权覆盖内。上线应保留来源链接、许可链接和处理说明，不直接搬运这些素材。
